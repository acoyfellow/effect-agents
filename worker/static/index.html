An experiment · May 2026

effect-agents

Five small AI agents, each in one file, built with Effect v4 (beta). One Cloudflare Worker hosts all of them. The point is to show what falls out for free once your agent is just an Effect value.

$ git clone https://github.com/acoyfellow/effect-agents
$ cd effect-agents && bun install
$ bun run smoke # all 5 run offline · no API key

The five

  1. 01 parallel-research Fan-out tool calls with bounded concurrency. Each call retries on its own backoff schedule, has its own deadline, and the final answer comes back as a typed object — not a JSON string you parse and hope.
  2. 02 streaming-tools Stream tokens and tool events through one channel. When the client disconnects, every fiber upstream — the model HTTP call, the tool handlers — gets cancelled cleanly.
  3. 03 approval-gated A destructive tool refuses to run until the caller approves it on a second turn. The "did the side effect happen yet?" question is a single field on the tool, not a state machine you build.
  4. 04 typed-errors The model's failure modes — rate limit, auth, network, content policy, bad output — are a tagged union. The handler maps each one to a precise HTTP status. No try / catch (e: any).
  5. 05 mcp-from-toolkit The same Toolkit value powers the agent and serves itself as an MCP server. Two surfaces, one source of truth. The agent and the MCP server can't drift.

Try it live

This page is the Worker. Every example is a callable endpoint:

POST /01           parallel-research
POST /02           streaming-tools (NDJSON)
POST /03           approval-gated turn 1
POST /03/decide    approval-gated turn 2
POST /04           typed-errors
POST /05           mcp-from-toolkit
*    /mcp          MCP HTTP transport
GET  /health
$ curl https://effect-agents.coey.dev/health
